DECO7180 — 原型相关问题

Question 1 — 描述原型的实体或数字形态

本原型是数字形态、浏览器内的单页应用，而非实体装置。通过 index.html 加载，在 #stage 中挂载 WebGL（Three.js）三维地球，页面周围为 HUD：标题区与状态、汇总标签（相对 2019 的 GDP 冲击、相对 2020 的复苏、焦点市场）、聚焦国家面板（病例、死亡、相对 2019 的 GDP、相对 2020 的复苏）、方法学 / 经济影响区域（GDP 柱状图与冲击条）、图例与滚动播报，以及带播放、「回到起点」与滑块的日度时间轴。交互方式为在地球上鼠标或触控（悬停、点击锁定国家）及时间轴控制，属于偏桌面端的数据探索原型。

Question 2 — 希望收集哪些具体指标、观察或用户反馈？

与辅导中强调的方法论证（问卷、访谈、观察、用户测试等）一致，可包括：

1. 任务型可用性：完成任务所需时间与错误。例如找到某国、跳到某日、读懂「相对 2019 的 GDP」与「相对 2020 的复苏」、仅凭面板（不仅地图颜色）判断是否处于深度冲击或复苏。
2. 理解与叙事：简短测后问卷或访谈。用户是否理解疫情扩散与宏观冲击或复苏的关联叙事、对数字的信任度、方法说明文案是帮助理解还是造成困惑。
3. 定性反应：出声思考或半结构访谈。注意力先落在地球还是图表、地图与数值面板的双重编码是冗余还是有助、对清晰度的改进建议。
4. 可选行为数据（若对会话做简单打点或录屏分析）：如悬停或探索的国家顺序、使用播放还是手动拖动时间轴、在某些日期区间的停留时间；服务于对探索模式的观察。
5. 与伦理相关的反馈（若讨论敏感汇总数据）：例如对国家层面健康数据与经济指标并列展示的接受度，以及对来源标注（如界面中的 sourceNote）的态度，与课堂中隐私、同意与设计责任的讨论相呼应。

当前代码库未内置生产级埋点；本题宜表述为在评估方案中计划如何采集，通过实验协议与可选轻量日志或录屏实现。

Question 3 — 设计如何支撑 Question 2 中的数据采集？

界面与交互被组织成可观察、可追问的任务结构：

1. 国家悬停与点击锁定（globe.js / app.js 中的 onCountryHover、onCountryClick）形成清晰的可观察路径：用户选哪些边界、是否会固定某一市场、偏重悬停还是锁定。支撑用时或错误类指标与访谈追问，例如「为什么选这个国家？」。
2. 日度时间轴（滑块、播放、2019-12 至 2023-12 标签）要求用户做时间导航；可观察拖动模式，并追问用户是否理解随时间变化而非静态地图。
3. 地球与右侧指标分离（病例/死亡对比 GDP 冲击/复苏及柱状图）便于检验用户是否整合流行病学层与宏观层，还是只关注其一，可以直接用理解类题目测。
4. 方法学卡片（GDP 路径、冲击标签、冲击条、各年柱）是显性的说明与论证界面；访谈可验证是否符合课程对论证与透明度的要求。
5. 工具提示与 aria-live 区域（#tooltip）便于将屏幕阅读器或包容性测试纳入方法组合。

总体而言，原型使每个评估问题对应具体的界面能力，与辅导中从研究缺口反向映射到方法与证据的思路一致。
