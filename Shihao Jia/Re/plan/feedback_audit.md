# DECO7180 Feedback Audit (A01 Recovery)

## Source

Tutor comment (grade: Marginal Fail) highlighted weak problem definition, unclear user group, and insufficient argumentation for why a visualization tool is necessary.

## Extracted Failure Points (Problem Definition Layer)

1. **Solution-first framing**
    - Current framing jumps to "how to visualize data."
    - The project does not first establish a user-level problem that requires intervention.

2. **User group is too broad**
    - Stakeholders are loosely defined.
    - No specific primary user with clear context, goals, and constraints.

3. **Weak necessity argument**
    - No strong case for why a visualization tool is needed over other forms (briefing, report, static summary).
    - Opportunity framing is "we have data, so we should visualize it," which is not sufficient.

4. **Dataset relationship exploration is shallow**
    - Patterns are identified, but relationship depth is limited.
    - Missing explicit treatment of what can and cannot be inferred.

5. **Evidence-to-claim chain is weak**
    - References are listed, but not clearly tied to specific claims.
    - Academic sources are not consistently used to justify design direction.

6. **Bias reflection is emerging but incomplete**
    - Some awareness exists, but no systematic bias-control method is documented.

## What Must Change (Recovery Direction)

- Move from **"visualization problem"** to **"user interpretation/decision problem."**
- Narrow to 1-2 primary user groups with explicit scenarios.
- Prove necessity: why this format and interaction are required for this user's unmet need.
- Build a claim-evidence matrix so every major statement is supported.
- Add explicit boundary statements for data interpretation and bias controls.

## Conversion to Actionable Work Items

- Produce `problem_statement_v2.md` with user-scenario-need framing.
- Produce `gap_matrix_rumsfeld.md` with knowns/unknowns/assumptions and research questions.
- Produce `research_plan.md` with mixed methods and justification mapping.
- Produce `design_brief_v2.md` translating evidence into requirements.
- Produce `prototype_test_plan.md` linking interface choices to measurable outcomes.

# DECO7180 反馈审核（A01 补救）

## 来源

导师评语（成绩：勉强及格）指出问题定义薄弱、用户群体不明确，以及对可视化工具必要性的论证不足。

## 提取的失败点（问题定义层）

1. **解决方案优先框架**

- 当前框架直接跳到“如何可视化数据”。​​

- 项目没有首先确定需要干预的用户层面问题。

2. **用户群体过于宽泛**

- 利益相关者定义模糊。

- 没有明确的主要用户及其背景、目标和限制条件。

3. **必要性论证不足**

- 没有充分论证为什么需要可视化工具而不是其他形式（简报、报告、静态摘要）。

- 机会框架是“我们有数据，所以我们应该将其可视化”，这不足以说明问题。

4. **数据集关系探索浅薄**

- 已识别出模式，但关系深度有限。

- 未明确说明哪些信息可以推断，哪些信息不能推断。

5. **证据到论断的链条薄弱**

- 列出了参考文献，但与具体论断关联不清晰。

- 未始终如一地使用学术资源来论证设计方向。

6. **偏见反思正在萌芽，但尚不完善**

- 已有一些意识，但尚未记录系统的偏见控制方法。

## 必须改进之处（改进方向）

- 从**“可视化问题”**转向**“用户解读/决策问题”**。

- 将用户群体缩小到 1-2 个主要用户群体，并明确其使用场景。

- 证明必要性：为什么这种格式和交互方式对于满足用户的未满足需求至关重要。

- 构建论断-证据矩阵，确保每个主要论断都有依据。

- 添加明确的数据解读和偏见控制边界说明。

## 转化为可执行的工作项

- 生成包含用户场景需求框架的 `problem_statement_v2.md` 文件。

- 生成包含已知/未知/假设和研究问题的 `gap_matrix_rumsfeld.md` 文件。

- 生成包含混合方法和论证映射的 `research_plan.md` 文件。

- 生成将证据转化为需求的 `design_brief_v2.md` 文件。

- 生成将界面选择与可衡量结果联系起来的 `prototype_test_plan.md` 文件。
