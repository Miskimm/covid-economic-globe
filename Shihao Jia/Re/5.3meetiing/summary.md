# 会议总结（基于 transcript.md）

## 1. 课程与迭代要求

- 方法论链条：**研究问题 → 假设 → 验证（含原型/用户测试）→ 反思与下一轮问题**。老师举例（如垃圾分类）：先提假设 → 用测试验证 → 再追问原因 → 再测，形成迭代。
- 老师希望约 **三轮迭代**；时间紧时小组约定大约 **一周一轮**。
- **每个人**都要有自己的研究线与假设，并能说明如何验证；**个体面试**会问到这套思路；后续周可能还要写成书面材料。
- 原型在迭代中的定位：**快速验证**，不必一开始就追求完美终稿。

## 2. 小组已对齐的项目决策

| 维度                                | 结论要点                                                                                                         |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **目标用户**                        | 从宽泛收窄为：**非数据科学专业的普通读者**，关心如何把图表读清楚。                                               |
| **为什么要做可视化**                | 报告里若只写「如何可视化」不够；要落到 **为何可视化**——如何呈现经济与新冠的关系、帮助理解。                      |
| **为何用两套数据（如 GDP + 疫情）** | 文献/论证上表达为：**放在一起呈现一种方向/趋势**（如疫情与经济表现的关联），需用研究依据支撑「为何选这些数据」。 |

## 3. 各人研究方向与假设（摘编）

- **注释与相关性**：图表增加注释是否更易读；数据若与用户「有关系」是否更引发兴趣。
- **强可视化 / 动态地球等**：假设精细、高互动可视化有助于理解；但 **用户测试反馈** 有例子显示 **过炫、过复杂反而加重认知负担（cognitive overload）**，需与假设对照迭代。
- **透明度与信任**：如何展示信息来源、方法、不确定性等，如何影响 **信任度与判断准确性**。
- **原型偏好 vs 解读质量**：有人偏好简洁、有人偏好沉浸；需探讨 **在控制偏好因素下，哪种原型交互带来更高的解读质量**。
- **指标理解度**：目标用户在多大程度上能正确解读跨时间、跨地区的健康/经济指标（如 Recovery vs 2019/2020、相关指数等）。
- **Dashboard vs 交互式可视化**：相对传统表格化 dashboard，交互式、可视化更强的界面是否 **更能吸引使用并促进理解**。

## 4. 用户测试与验证方式

- 已有：**用纸面/低保真原型做访谈**、多版本原型对比、问卷等思路。
- 讨论到 **打分表**：按任务拆解维度（如误读类型、时间轴混淆、虚假因果等），对每次访谈打分汇总，用于判断界面或解释设计的优劣。
- **证据材料**：访谈时可留 **卡片、照片、纸质记录**；是否必须录音/视频以老师当周要求为准，小组内有「模拟结果 / 纸质流程也可」的讨论，**以课程正式说明为准**。
- 写作上建议：**本周聚焦「当前研究问题 → 做了什么测试 → 结果与结论 → 催生下一问」**，避免重复罗列早已回答过的旧 research question；论点尽量 **配文献**。

## 5. 协作与终期展示

- 担心各人方向过散、难以合成一个 **小组最终作品**；建议建 **共享文档/页面**，同步每人课题与进度。
- **不必过早锁定「final prototype」**；先各自推进验证，后续再整合叙述或原型。
- 有人提到展示环节可用 **AI 辅助叙事整合**，但核心仍是每人清晰的 research line 与验证链。

## 6. 时间与周次（听录混杂处）

- 录音中对「第几周 / 下一轮 iteration」有口误和来回确认；**以教学大纲与老师公布的周次为准**。大意是：**本周推进设计与验证，后续周继续第二、三轮迭代**。
- 建议在群里 **每周同步各自的 research question**，必要时形成简短周记/文档，便于对齐。
