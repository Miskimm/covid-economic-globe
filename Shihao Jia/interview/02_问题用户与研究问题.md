# 概括性问题：为什么做、为谁、研究什么

> **Weekly activity 主轴**：W4–5 已写问题含伦理/信任；W9 写「RQ 未锁就开工」后的转向。Tutor 若问「学期初 vs 现在」→ 先翻 [打印摘录](./weekly_activity_Shihao_打印摘录.md) W4–5、W9，再指 `problem_statement_v2.md`。

## Q1. 为什么要设计这个 prototype？

### 短答（20 秒）

公开数据很多，但目标用户**无法可靠地解读**健康与经济的跨国、跨时间关系，也**难以在作业里论证**自己的说法。我们要做的是**interpretation + evidence**，不是再做一个图表墙。

### 长答（带 A01 转向）

- **W5 weekly（你的原话）**：问题空间是冷统计与大众理解之间的 **messy middle**；设计义务是让 **uncertainty and inequality visible**——不是证明「COVID → X% GDP」简单规则。
- **早期问题（被 tutor 批评）**：solution-first——「有数据就要可视化」。
- **W9 weekly**：W6 任务太开放，界面反映「好看」而非可测证据 → **回到 problem define**（与 A01 一致）。
- **补救后的问题（`problem_statement_v2.md`）**：
  - 核心缺口：**interpret and justify** health–economy linkage；
  - 需要：指标语义、可追溯比较、区分证据与假设、理解不确定性。
- **必要性论证**：静态报告/简报无法提供**同屏对照 + 即时定义 + 结构化自检**；我们的交互是为**降低误读成本**而设计，不是为了炫技。

### 可引用金句

> "The key problem is **not** that data lacks visualization. The key problem is that target users lack a reliable way to **interpret and justify** health-economy relationships."  
> — `Re/plan/problem_statement_v2.md`

## Q2. 目标用户是谁？

### 主用户（Primary）— 面试默认说这组

| 维度 | 描述 |
| --- | --- |
| **Who** | 政策、经济相关、设计、传播等课程的本科/研究生 |
| **知识** | 懂 GDP、失业率等基础词，**不是**计量/宏观专家 |
| **场景** | 作业、research、课堂展示——要讨论疫情对经济的影响 |
| **痛点** | 能看单图，但连不起指标；把「喜欢界面」当成「懂了」；容易把相关说成因果 |

### 次用户（Secondary）

- 关注新闻的公众：想比较国家/时期，但被多源仪表盘淹没，且不信来源不明的图。

### 团队口径（5.8 会议）

与上述一致，强调「**学过经济课但非专家的学生**」。

## Q3. 你的 Research Questions 是什么？

来自 `gap_matrix_rumsfeld.md`，面试说 **2–3 个**即可：

| RQ | 问什么 | 你怎么验证 |
| --- | --- | --- |
| **RQ1** | 用户能否**准确解释**所选健康/经济指标的关系？ | 指标定义题、比较题、开放解释题（三轮测试） |
| **RQ2** | 哪种界面形式更能支持**有效理解**（而非仅偏好）？ | 卡片 vs 多屏流 vs 渐进画布；分离 preference / correctness |
| **RQ3** | 哪些信任/透明线索能改善**信任校准**？ | 来源面板、局限自述、trust gate |

**Gap 优先级**：A 解读有效性 > B 信任 > C 形式偏好。

## Q4. 为什么必须是「交互式工具」而不是 PDF / 静态图？

| 需求 | 静态媒体的局限 | 原型的应对 |
| --- | --- | --- |
| 跨国同时对照 | 多张图难对齐年份与指标 | 对比槽 + 对齐表格 |
| 指标语义 | 脚注常被跳过 | 同屏 badge + chip / AI 解释 |
| 论证边界 | 读者容易自行脑补因果 | boundary self-check、局限任务 |
| 探索动机 | 纯表格式枯燥 | 地球 + 时间轴（团队） |

## Q5. 设计需求 R1–R5 是什么？（若被问「你的 design requirements」）

来自 `design_brief_v2.md`：

- **R1** Interpretation clarity — 每个核心指标有白话解释；支持 before/after、跨国比较。
- **R2** Preference–understanding separation — 评价时分开：喜不喜欢 / 解释对不对 / 信心是否校准。
- **R3** Trust transparency — 来源、方法、不确定性在**使用点**可见。
- **R4** Cognitive load control — 一屏一个主任务，避免信息墙。
- **R5** Evidence traceability — 每个设计选择能指回研究或 tutor 反馈。
