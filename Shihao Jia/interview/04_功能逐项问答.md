## 地球 / 3D 可视化

### Q. 为什么用 3D 地球，而不是纯 dashboard？

| 理由类型 | 内容 |
| --- | --- |
| **团队决策** | 5.8 会议：保留地球作主界面；静态方案更清晰但小组仍选 globe + 优化 |
| **用户/场景** | 全球疫情+宏观数据天然是**空间问题**；地球提供「我在看整个世界」的锚点 |
| **研究警示** | 个人 low-fi：地球有 engagement，但**不能证明理解** → 必须叠加解读层 |
| **折衷** | 提供 **2D toggle**（`README.md`）给读数/眩晕敏感用户 |

### Q. 地球为什么要旋转？（高频）

**weekly activity 依据**：W7 你写「不熟悉地理会反复旋转、误点邻国」→ 团队加搜索（5.8）；Hongbiao W10 记「旋转吸引注意力、难去看其他内容」——你的整合答法：**旋转=探索入口，不是论证工具**。

分三层答，避免只说「好看」：

**1. 自动旋转（idle animation）**

- 代码：`globe.js` 中未拖拽时 `globeGroup.rotation.y += state.yawVelocity`，并有微弱持续加速度；外壳 `outerShell` / `atmosphere` 反向微转增强层次。
- **设计意图**：
  - **展台/探索感**：静态球像海报；缓慢旋转暗示「可交互、有时间维度」。
  - **暗示全球尺度**：强化「跨国比较」心智模型。
- **不是**：为了帮用户算数——读数在侧栏/2D/对比表。

**2. 用户拖拽旋转**

- **意图**：无搜索时靠旋转找国家（课程材料 `od/weekly activity.md` 也提到地理不熟会反复转）。
- **已知代价**：旋转负担、可能误点邻国 → 团队加 **search** 减旋转（5.8 会议）。

**3. 与测试的关系（诚实）**

- 文献/方案讨论：`solution4.md` — 3D 旋转可能带来**空间混淆**。
- 个人线结论：旋转 ≠ 理解；所以旋转是**入口动效**，论证任务放在**对比+来源+解释**。

**演示句**：「If you already know the country, use search — rotation is for exploration, not for proof.」

### Q. 点击国家后发生什么？

- Raycast 边界 → `onCountryClick` → 侧栏显示 cases、deaths、GDP shock、recovery（`README.md`）。
- 设计分工：**地球 = where**；**面板 = what + so what**。

### Q. 时间轴为什么按「日」？

- `timeline.js`：2019-12-01 至 2023-12-31 日粒度，支持拖拽与播放。
- **理由**：疫情曲线需要日级变化；经济年指标在面板层聚合展示。
- **面试注意**：若被问「GDP 与日轴对齐」，答：可视化层用日轴驱动**疫情**；经济序列在数据层按年/可用频率对齐，并在来源框说明（你的分工）。

### Q. 2D / 3D 切换为什么存在？

- 会议：兼顾偏好；2D 更利于**读数与截屏进作业**；3D 更利于展示吸引力。
- 切换应**保留选中国家与时间上下文**（`result.md` §2.6）。

## 多区域对比（你的分工 ⭐）

### Q. 为什么需要对比功能？

| 测试 | 发现 |
| --- | --- |
| Low-fi | 给两国两时点，**7/10** 能识别 UK 冲击更深（-12.0 vs -3.7 pp） |
| Mid-fi | Task 2 有数字，**Task 3 开放题引用衰减** |
| Hi-fi | 原型内 6/6 有数字，但问卷 3a 仍 2/6 无数字 |

→ 对比模块要让数字**始终可见**，并支持**复制引用串**。

### Q. 对比具体怎么做？（口述 MVP）

1. 槽位 A/B（可选第三国）：搜索或地图「加入对比」
2. **对齐**：同一指标、同一年份窗（如 2020 vs 2023）
3. **高亮**：2020 GDP gap 等关键格
4. **输出**：`UK GDP gap 2020: −12.0 pp; Australia: −3.7 pp (sources: …)`
5. 可选：结论框轻提示「须含页面上的数值」

### Q. 为什么示例常是 UK vs Australia？

- 测试刺激材料固定：差异大（−12.0 vs −3.7），便于观察用户是否会**过度因果**（病例与 GDP 并排时）。

## 来源框 / 数据可信度（你的分工 ⭐）

### Q. 为什么要来源框，只写 World Bank 不够吗？

- Low-fi：**6/10** 要公式、原始链接、缺失值说明；**8/10** 信任低时直言「只有名字不够」。
- Mid-fi：有人 trust 5 分但未开方法面板。
- Hi-fi：trust gate 强制先写局限，但 S03/S06 有**最短字数糊弄**。

### Q. 来源框四层结构（建议背诵）

1. **Citation line** — 数据集 + 机构 + 访问日期  
2. **Variable dictionary** — 缩写、单位、基准年、是否 pp  
3. **Merge logic** — OWID 健康 + WB 经济如何 ISO3–year 对齐；缺失如何显示  
4. **Epistemic boundary** — 三条固定话术：共同变动≠因果；病例跨国不可直接比；GDP 滞后/修订  

### Q. Trust gate 是什么？团队版要不要？

- Hi-fi：未写局限 ≥8 字则 trust 按钮不可用；**6/6** 先写局限。
- 团队可采纳为：**打分前先写一条局限**（下拉提示 + 自由文本），防止「看着专业就满分」。

## AI 解释

### Q. 为什么加 AI？会不会幻觉？

- **动机**：mid-fi primer 被跳过 → 把定义放在**指标旁的 ?**，在误读发生时刻介入。
- **治理**（必须说）：AI **只解释页面上已有**的指标、数值、来源；不编造国家/年份；无法回答时提示「请加入对比/切换国家」。
- **与 chip 分工**：静态 chip 第一层（无 API 成本）；AI 第二层。

### Q. Recovery 为什么要特别强调不是健康恢复？

- Low-fi：S05、S07、S10 混淆；S02 建议改名 **economic recovery**。
- Hi-fi：**ECONOMIC** badge + chip 文案；prompt 模板固定一句 disambiguation。

## 指标：GDP gap、Recovery、pp

### Q. 「GDP vs 2019」是什么意思？

- 当前 GDP 相对 **2019 疫情前基准** 的差距，单位 **percentage points (pp)**，负值=仍低于 2019。
- 不是 GDP 绝对额，也不是简单百分比增长率混淆。

### Q. 「Recovery vs 2020」是什么意思？

- 自 **2020 低谷（trough）** 以来经济反弹了多少 pp。
- **不同于** GDP gap：可以 recovery 很大但仍低于 2019（UK 案例 mid-fi/hi-fi 常考）。

### Q. 为什么用 pp 不用 %？

- 测试里 **4/10** baseline/pp 混淆；需在 chip 里用例子解释「−12.0 pp = 比 2019 低 12 个百分点」。
